# Archived ledgers

An append-only ledger is never edited, so one that turns out to be unpublishable
is retired here rather than corrected. Nothing in this directory is deleted.

## canary-*-dev.sqlite3 (retired 2026-10-03)

Retired because sighting 1 in it is the operator's own `curl/8.5.0` probe,
recorded with `origin='organic'` by a build that stamped one process-wide origin
on every row. Mechanically a true sighting; worthless as evidence, and
misleading if published as third-party traffic.

It is kept because it is the evidence for the fix: `origin` is now resolved per
request (`request_origin()` in `canarymaze/app.py`), and the operator's own
probes are counted as `selftest` and never folded into `organic`.

Contents: 4 mints, 7 requests, 1 sighting - all generated by the operator. No
third-party traffic, and no human was ever stored in it.

The live surface now writes to `ledgers/canary-public.sqlite3`.

## canary-public-*-polluted.sqlite3 (retired 2026-10-03, hours after the first)

Retired because four of its sightings, all marked `organic`, are the operator's
own diagnostic `curl`s. They were sent while investigating why a crawler received
403 from the edge, without the self-test token, because the token was opt-in and
was forgotten for the third time - the third time being *while diagnosing the
second*.

That is what moved the control. A token the operator must remember on every probe
is not a control; it is a reminder. The surface now recognises the operator's own
networks (`CANARY_OPERATOR_NETS`) with no cooperation from the client at all, and
the token remains only for probing from somewhere else.

Contents: 5 mints, 9 requests, 4 sightings - every row the operator's own. No
third-party traffic. The live ledger is now `ledgers/canary-public-2.sqlite3`.

## canary-public-2-*-unstable-context.sqlite3 (retired 2026-10-03, the third)

Retired because its context ids cannot be trusted. The fingerprint that produced
them hashed the name of every request header it saw - including the ones the
hosting platform injects, which are a different set on different routes. So one
client that fetched a maze page and then followed its own canary link came out as
two contexts, and the ledger recorded a sighting for the commonest harmless event
there is.

It was found by testing for it directly, from the operator's own network, so the
false sighting it produced is labelled `selftest` and never touched the organic
count. No third-party traffic had been recorded under the broken derivation.

The context is now derived from an allowlist of client headers only, with order
ignored, and the edge forwards nothing else (F-0006). The live ledger is
`ledgers/canary-public-3.sqlite3`.
